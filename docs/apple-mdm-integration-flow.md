# Apple MDM Integration Flow — Setup Reference

This document describes the modern architecture and setup flow for running NanoMDM with Supabase and Render, integrated with our primary backend (`lockapp-server` on Vercel).

---

## 1. High-Level Architecture

```
  +-----------------------+              +-------------------------------------+              +-----------------------+
  |    lockapp-server     |  REST API    |       NanoMDM Engine on Render      |  PostgreSQL  |      Supabase DB      |
  |     (on Vercel)       |<------------>|       (Free Docker Web Service)     |<------------>|  (Managed PostgreSQL) |
  | Handles business logic|   Webhooks   |  Zero OS admin, Auto-SSL custom domain|  Connection  | Zero DB maintenance   |
  +-----------------------+              +-------------------------------------+              +-----------------------+
```

- **Our Backend (`lockapp-server`)**: Hosted on Vercel. Handles credits, shopkeepers, customer activation keys, payment tracking, and lock/unlock triggers.
- **NanoMDM Engine**: Runs as a lightweight Docker container on **Render**. Handles Apple MDM protocol (plist/APNs), receives device check-ins, and manages command queues.
- **Supabase (PostgreSQL)**: Managed cloud database storing NanoMDM protocol state (push tokens, device UDIDs, command queue). Decoupled from `lockapp-server`'s database.
- **UptimeRobot**: Free keep-alive service pinging NanoMDM every 10 minutes to prevent Render free-tier container sleep.
- **Apple Infrastructure**: Delivers APNs push notifications to devices.

## 3. Storage & Hosting Configuration

- **MDM Hosting**: Render (Free Docker Web Service).
- **MDM Storage**: Supabase Cloud PostgreSQL (connected via `POSTGRES_STORAGE_DSN`).
- **Domain & SSL**: Render custom domain with automatic TLS (`mdm.yourdomain.com`).
- **Keep-Alive**: UptimeRobot or Cron ping every 10 minutes hitting `/healthz`.

---

## 4. Integration Flow with Backend (`lockapp-server`)

### 4a. Incoming: NanoMDM → `lockapp-server` (Webhooks)
- NanoMDM POSTs device event payloads to `https://ourbackend.com/api/mdm-events`.
- Processes `TokenUpdate` events (UDID + PushToken) and links them to customer activation keys in backend DB.
- Receives command execution acknowledgments.

### 4b. Outgoing: `lockapp-server` → NanoMDM (REST API)
- Backend calls NanoMDM REST API (`POST /v1/commands/{udid}`) authenticated with API token.
- Enqueues commands: `DeviceLock`, `ClearPasscode`, `EraseDevice`.
